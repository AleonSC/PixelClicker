# Pixel Clicker – project notes

3D incremental clicker in Unity (C#, TextMeshPro). All code lives in `Assets/Scripts/`. Everything UI is built at runtime (no prefabs/scene UI required). Nothing has been compiled or run by Claude – the user tests in Unity.

## Core architecture

| Script | Role |
|---|---|
| `PixelClicker.cs` | Core. Owns the `PixelTier[]` list, currency counts/totals, click handling (raycast), spawn/materialize/pulse/hover/spin animation, old-pixel "falling copy" physics (half-size copies, pop in tiny + no collision, swell-and-shrink despawn), vacuum suction, shared UI font (`UIFont`), `FormatNumber` (public static). Also defines helper MonoBehaviours `ScaledGravity` and `OldPixelInfo` at the bottom of the file. |
| `PixelFind.cs` | `PixelFind.First<T>()` / `Count<T>()`: the only place with the `FindFirstObjectByType` / `FindObjectOfType` version check. Use it instead of calling Unity's Find methods directly. |
| `PixelUIKit.cs` | Shared static helpers for code-built UI: `EnsureEventSystem`, `CreateCanvas`, `CreateText`, `CreateButton`, `Stretch`, `CreateDropdown`, `CreateInputField`, `CreateScrollView`/`UpdateScrollView` (masked scroll list + auto-hiding scroll bar). UI scripts delegate to it instead of carrying their own copies. |
| `PixelMinigame.cs` | Abstract base for minigames (registry `PixelMinigame.All/Find(id)`, `Id`, `Running`, `Activate/Deactivate`, optional goal tracker: `HasTracker`, `TrackerTitle/Description/Count/Goal`, `RequirementFormat`, `GoalReached`). Bought minigames get an on/off row in the Toggles window (`PixelMinigame.UserDisabled`, saved per minigame; the shop never auto-starts a disabled one). Shop packs refer to minigames by id (`unlocksMinigame`; goals via a `PackRequirement` of kind `MinigameGoal`); the shop shows tracker rows and the save system stores counts generically - **a new minigame needs no changes to PixelShop or PixelSaveGame**. |
| `PixelBlackholeMinigame.cs` | Black hole minigame (Minigames tab, a pack with `unlocksMinigame = "blackhole"`): random-size swirling hole (runtime-drawn spiral textures) opens on the floor; old pixels inside are taken via `PixelClicker.ReleaseOldPixel` and spiral in, stretched (spaghettification). Owns the **singularity tracker** (`SingularityCount` / `SingularityThreshold`, saved); extends `PixelMinigame` (id `blackhole`); the Singularity Pixel pack has a `MinigameGoal` requirement for `blackhole`. Shop shows the tracker row on the Minigames tab. |
| `PixelGhostMinigame.cs` | Ghost minigame (bought in the shop's Minigames tab via a pack with `unlocksMinigame = "ghost"`): a faint wobbling cube floats across the screen at random intervals; clicking it calls `PixelConsumables.GrantRandomBuff` (free random unlocked-pixel potion) and counts toward `GhostsCaught` (saved); extends `PixelMinigame` (id `ghost`); the Ghost Pixel pack has a `MinigameGoal` requirement for `ghost`. PixelShop finds/adds this component. |
| `PixelMeteorMinigame.cs` | Meteor minigame (pack `unlocksMinigame = "meteor"`, Minigames tab): a large glowing meteor drifts slowly across the screen; each click gives `chunksPerClick` meteor chunks but never destroys it. Tracker "Meteor Chunks" (saved generically); the Meteor Pixel pack has a `MinigameGoal` requirement for `meteor`. Extends `PixelMinigame` (id `meteor`). |
| `PixelBombMinigame.cs` | Bomb Defusal minigame (pack `unlocksMinigame = "bomb"`, Minigames tab, needs the RGB pack): every 2-4 min a code-built bomb (casing, countdown text, red/green/blue wires with fat click hitboxes) appears beside the cube; click the wire of the RGB pixel with the highest `count` at click time (`CorrectWire`) before `timeLimit` to defuse (+`partsMin..partsMax` **bomb parts**, the tracker count, saved generically, spendable via `TrySpendParts` for future systems); wrong wire or timeout = explosion flash + `PixelClicker.ClearOldPixels()`. Extends `PixelMinigame` (id `bomb`); sounds `bomb_spawn/_click/_tick/_explode`. |
| `PixelPadMinigame.cs` | Ultra Pad minigame (pack `unlocksMinigame = "pad"`, Minigames tab, needs the RGB pack): a coloured square pad spawns on the floor for `padSeconds` wanting old pixels of ONE pixel type (random unlocked tier, the pad shows its colour + a label); any old pixel that lands on it is taken in (`ReleaseOldPixel` + `OldPixelDespawn.Begin`): the right type has `ultraChance` of `PixelClicker.AddUltra`, any other type is penalised via `PixelClicker.RemoveCurrency(tier, info.amount)` (never below 0, not counted as spending). **Ultra counts live on `PixelTier.ultraCount`** (saved in `TierSave`; `GetUltra`, `TotalUltra`) for future upgrades; the minigame's tracker shows the total. PixelUI shows a hover tooltip ("Ultra X: n", `PixelHoverTip`) on each pixel entry while `PixelPadMinigame.UltraVisible`. Extends `PixelMinigame` (id `pad`); sounds `pad_spawn/_click/_wrong/_ultra`. |
| `PixelCombo.cs` | Combo meter (shop upgrade "Combo Meter", `UpgradeEffect.ComboMeter`, 5 levels; level value = max multiplier): quick manual clicks build a combo (+5% each, breaks after 1.2 s idle); sets `PixelClicker.ManualClickBonus` every frame (applied to manual payouts only); meter drawn at the bottom-centre of the screen. PixelShop finds/adds it and applies it via `SetUpgrade`. |
| `PixelCrafting.cs` | Crafting (shop pack with `unlocksCrafting`, Upgrades tab): bottom-right "Crafting" button opens a window with two drop boxes, a recipe/cost readout, a Craft button and a scrolling grid of owned items (pixel types with currency as spinning cubes; potions as a glass cube with a smaller pixel cube inside). Drag (or click) grid items into the boxes; `Recipe` list in the Inspector (two ingredients, pixel currency or potions, any order -> a potion or device); defaults = each pixel + Glass -> that pixel's potion; plus automatic combo recipes (potion + a non-toggleable pixel -> `PixelConsumables` craft-only combo potion that spawns both types via `PixelClicker.SetForcedSpawnTiers`; combo potions are generated at runtime in `AppendComboPotions`, flagged `craftOnly`, hidden from the shop, saved with a `second` type). Right-click a box to empty it. Spends via `PixelClicker.TrySpend` / `PixelConsumables.TryRemoveItem`, adds via `AddItem`. PixelShop finds/adds it. |
| `PixelToggles.cs` | Toggles window: a button docked to the **middle of the right edge** (`PixelHud.Dock` with anchor (1, 0.5) = side docking, slides sideways) opens a window with three group buttons (Pixels / Upgrades / Minigames) over a scrolling list of tick-box rows. Pixels = `SetSpawnEnabled` for switchable unlocked tiers; Upgrades = `PixelAutoClicker.UserDisabled` and `PixelGrab.UserDisabled` (both saved by PixelSaveGame; `Working` = bought and not switched off); Minigames = `PixelMinigame.UserDisabled`. **This replaced the tick boxes that used to sit on shop rows.** The pause menu adds this component if missing. |
| `PixelGrab.cs` | Pixel Grabbing (shop pack with `unlocksGrabbing`, Upgrades tab): hold left mouse on an old pixel (sphere-cast, `grabRadius`) to drag it on the camera-facing plane through it (rigidbody velocity follows the mouse, so it still collides), release to throw (`throwStrength`, `maxThrowSpeed`); a held pixel's `OldPixelDespawn.Held` freezes its lifetime and its `ScaledGravity` is paused. Sets `PixelClicker.GrabEnabled` so clicks on old pixels no longer pass through to the cube. Sounds `grab`/`drop`. PixelShop finds/adds it. |
| `PixelTimeStop.cs` | Time Stop (shop pack with `unlocksTimeStop`, Upgrades tab): press T to set `Time.timeScale = 0` (everything incl. countdowns; clicks ignored like the pause menu) and again to resume; re-applies the freeze after the pause menu closes; shows a "Time stopped" text under the top bar; switch in the Toggles window (`UserDisabled`, saved). Sounds `time_stop`/`time_resume`. PixelShop finds/adds it. |
| `PixelHud.cs` | Screen frame: black bar along the top and bottom (`barHeight`) and the **docked buttons**. `PixelHud.Ensure(gameObject)` then `hud.Dock(buttonRect, anchor(0|1,0|1), keepOutWhile)` gives a button the standard `ButtonSize` and makes it slide off screen (only a `sliver` shows) until the mouse is near (`PixelDockedButton`); it stays out while its window is open. Windows that open from a docked button use `hud.SideMargin` / `hud.WindowOffset` for position; top/bottom-anchored overlays add `PixelHud.Instance.BarHeight`. Used by Inventory, Shop, Log and Crafting buttons. The pause menu adds this component if missing. |
| `PixelAudio.cs` | Sound system. Named `Sound` list (id, clips[] picked at random, volume, pitch range, cooldown) filled in the Inspector - an empty/unknown sound is silent; music tracks (shuffle/loop); Master/Effects/Music volume + mute (saved in PlayerPrefs, sliders in the pause menu's Settings via `PixelUIKit.CreateSlider`); a voice pool. Plays by itself from existing events (clicks `click`/`auto_click`/`pixel_<type>`, `hit`, `vacuum`, `pixel_land` (from `OldPixelImpact` -> static `PixelClicker.OldPixelLanded(intensity)`; volume scales with impact speed), `combo` (pitch rises), `purchase`, `craft`, `drink`, `device_place`, `achievement`, `<minigame id>_spawn/_click`, `ui_click` from every `PixelUIKit.CreateButton` (the shop adds its own), `ui_scroll` from `PixelScrollSound` which is added to every ScrollRect the game builds); other code calls `PixelAudio.Play("id")`. The older per-script sound slots (purchaseSound, drinkSound, craftSound, caughtSound, hitSound) still exist. The pause menu adds this component if missing. |
| `PixelInput.cs` | Static input helpers for both input systems (`PointerPosition`, `LeftPressed`, `RightPressed`, `PointerOverUI`); minigames/consumables use `using static PixelInput;`. |
| `PixelPlacedDevice.cs` | Abstract base of placed devices: countdown, timer text facing the camera, shrink-away (`InitCommon`, `OnTick`, `IsDying`). |
| `PixelFanDevice.cs` | (extends PixelPlacedDevice) Runtime behaviour of a placed fan (device `kind` = Fan): pushes old pixels inside a floor wedge (cone angle/length/height) along its forward, spinning blades, timer. Placed like the vacuum, turned with scroll wheel or Q/E while placing. |
| `PixelVacuumDevice.cs` | (extends PixelPlacedDevice) Runtime behaviour of a placed vacuum device (cylinder): pulls old pixels in its radius, `PixelClicker.AbsorbOldPixel`, timer text above it, shrinks away at 0. Built by PixelConsumables. |
| `PixelConsumables.cs` | Potions (one per pixel type, editable list: name, type, costs, duration, owned) and placeable devices (Vacuum Device: right-click in inventory → cylinder follows mouse → left-click floor to place; right-click cancels). Unified `Item*` accessors (potions first, then devices) used by shop/inventory/save. Drinking one calls `PixelClicker.SetForcedSpawnTier` for its duration. PixelShop sells them (Consumables tab); PixelShop auto-adds this component if missing. |
| `PixelUI.cs` | "Inventory" toggle box (top-left) with Currency / Consumables tabs (right-click a potion to drink), active-potion timer and a tier guide ("Click X more Y pixels..." / "Y pixel unlocked") at top of screen; Currency tab: per-tier counts, cursor `+N` popups (manual) / cube popups (auto), vacuum `+X` total popup, per-entry vacuum `+X` indicators. Builds in `Start()` so shop-added tiers are included. |
| `PixelShop.cs` / `PixelShopUI.cs` / `PixelShopDefaults.cs` | One `partial class PixelShop` in three files: **PixelShop.cs** = data types, ALL `[SerializeField]` settings, lifecycle, buying/requirement logic; **PixelShopUI.cs** = building and refreshing the UI (button, panel, tabs, scroll list, upgrades window, trackers); **PixelShopDefaults.cs** = the built-in pack definitions (`Create…Pack`) plus the `BuiltInPacks` table (how to recognise each one, which pack it requires, how to build it) - **to add a built-in pack: write its `Create…Pack` and add one line to the table**. Keep new serialized fields in PixelShop.cs so the Inspector order stays stable. Shop button (appears once `requiredTier` = Black is unlocked) + panel. `ShopPack` list: RGB Pack, Auto Clicker, Glass Pixel, Vacuum Pixel, Obsidian Pixel, Luminescent Pixel (Pixels tab), Faster Clicking, Multi-Click, Combo Meter, Crafting, Pixel Grabbing (Upgrades tab), Ghost Hunt, Black Hole, Bomb Defusal, Ultra Pad (Minigames tab), Singularity Pixel (Pixels tab, gated by the singularity tracker), Ghost Pixel (Pixels tab, gated by ghosts caught), Meteor Strike (Minigames tab, needs Obsidian), Meteor Pixel (Pixels tab, gated by meteor chunks). The Minigames tab shows one tracker row per minigame that has a goal counter. The Upgrades tab has two sub-tabs: "Upgrades" (the packs) and "Pixel" (Ultra boosts: one row per unlocked pixel type, `PixelTier.ultraLevel`, cost `ultraBaseCost + level * ultraCostPerLevel` Ultra pixels, payout x `1 + level * PixelClicker.ultraBonusPerLevel` via `UltraMultiplier`). Four tabs (Pixels / Upgrades / Consumables / Minigames; per-pack `tab`, `Automatic` infers it) over a fixed-size scrolling list (ScrollRect + scrollbar). Leveled packs that require another pack (the auto clicker upgrades) are not in a tab: the required pack gets an arrow button opening a second "Upgrades Window". Each pack has a `requirements` list (`PackRequirement`: kind `Pack` = another pack index must be bought, kind `MinigameGoal` = a minigame id's goal reached; all must be met; `ShopPack.ParentIndex` = first Pack requirement, used to file upgrade packs under their parent). Handles buying, requirements, affordability colouring, levels/upgrades, Inspector-ticked `purchased`. `[RequireComponent(typeof(PixelAutoClicker))]`. |
| `PixelShopConsumables.cs` | Third-and-a-half part of `partial class PixelShop`: the Consumables tab = two **purchase cards** (Potions, Utilities/devices) side by side, each with an item drop-down (locked items shown in grey text), a count box with -/+ and a Buy button; `TryBuyItems(item, count)`. Hides the scrolling list while that tab is open. Craft-only combo potions are never listed. Settings are in PixelShop.cs. |
| `PixelAutoClicker.cs` | Timer that calls `clicker.AutoCollect()`; `Interval` / `ClicksPerTick` properties; `Activate()` from shop; `startRunning` for testing. |
| `PixelAchievements.cs` | Modular achievements: Inspector list of `Achievement` (id, title, description, `Kind`, pixelType, target). New goal types = add a `Kind` value + a case in `GetProgress`; or `Register(achievement, Func<double>)` from code. Achievements have tiers (`tiers[]`, `earnedTiers`); defaults per pixel type: tiered "Collect" (lifetime value, `totalCollected`: 10, 100, 1K, 10K, 100K, 1M) and tiered "Click" (`PixelTier.timesCollected`, saved: 10, 50, 250, 1K, 5K, 25K; `Kind.ClickPixelType`). Saved as "id:tiers". Unlocks quietly/with popup, ids saved by PixelSaveGame. Auto-added by PixelLog. |
| `PixelCubeIcon.cs` | UI `MaskableGraphic` drawing a tiny spinning shaded 3D cube (no camera/render texture) - achievement icons. |
| `PixelLog.cs` | Bottom-left "Log" toggle with two tabs: Pixels (unlocked tiers with lifetime totals, overall total, vacuum `+X` deltas) and Achievements (scrolling list with progress bars + spinning cube icons; a pixel's Collector + Clicker achievements share one row, click it to switch, remembered in PlayerPrefs). Has its own local `FormatAmount`. |
| `PixelSaveGame.cs` | Save/load to JSON in `Application.persistentDataPath` (tiers, shop packs by name, auto clicker, potions owned). Loads on start (1 frame delayed), autosaves, saves on quit. Pause menu has Save / Load buttons; Restart deletes the save. Uses `PixelClicker.LoadTierState/FinishLoad` and `PixelShop.SetPackState`. |
| `PixelOfflineProgress.cs` | Offline progress: `PixelSaveGame` stores `savedAtTicks` (UTC) on every save and, on the startup load only, calls `Grant(lastSaved)`. If the auto clicker is running it pays the average earnings for the (capped, scaled) time away - clicks = time x efficiency / interval x clicks-per-tick, split across unlocked tiers by spawn weight, tough pixels needing several clicks - and shows a "Welcome back" window. Settings: max hours, efficiency, minimum away time. |
| `PixelStats.cs` | Play stats (manual/auto clicks via `PixelCollected`+`PixelHit`, play time excluding pause, pixels spent via `PixelClicker.CurrencySpent`; plus ghosts/meteors clicked, meteors/black holes spawned via static `PixelMinigame.Happened`, fans/vacuum devices placed via `PixelConsumables.DevicePlaced`, potions used per name via `PixelConsumables.PotionDrunk`, highest combo via `PixelCombo.ComboReached`); saved by PixelSaveGame (`ExtraData`); shown in the pause menu's Stats section (scrolling list + collapsible "Potions used" box). |
| `PixelWindows.cs` | Static registry of closable windows (placing a device 100, shop upgrades window 40, shop 30, log 20, inventory 10). Escape closes the topmost one; the pause menu only opens on Escape when none is open. New windows should `PixelWindows.Register(this, priority, isOpen, close)` and `Unregister(this)` in OnDestroy. |
| `PixelPauseMenu.cs` | Pause menu (Esc; the on-screen Pause button is off by default - `showPauseButtonOnScreen`): sets `Time.timeScale = 0`, Resume / Save+Load / Stats+Settings / Restart / Quit (Settings: tick boxes for cube rotation, pulsing and "Abbreviate numbers" -> `PixelClicker.AllowRotation/AllowPulsing` and static `PixelClicker.AbbreviateNumbers` (read by `FormatNumber`, `PixelUI`, `PixelLog` and the stats), stored in PlayerPrefs), `PixelPauseMenu.IsPaused`. PixelClicker ignores clicks while `Time.timeScale <= 0`. |
| `PixelPauseMenu` changelog | Changelog button/screen reads `Resources/Changelog.txt` (see Changelog workflow below). |
| `PixelDevTools.cs` | Dev tools (Editor/dev builds only; removes itself otherwise): a "Dev Tools" button in the pause menu (shown via `PixelDevTools.Available`) opens a panel: pixel dropdown + amount field + Add, add-to-all, minigame dropdown + Spawn (`PixelMinigame.SpawnNow`/`DisplayName`), Unlock all shop items (`PixelShop.DevUnlockAll`), tick box for Q = `PixelClicker.ClearOldPixels`. Uses `PixelUIKit.CreateDropdown/CreateInputField`. Escape closes the panel first. |

### Data model
- `PixelTier`: name, colour/`UIColor`, `PixelType` enum (White, Gray, Black, Red, Green, Blue, Glass, Vacuum, Obsidian, Luminescent, Singularity, Ghost, Meteor), `TierUnlockMode` (PreviousTierThreshold / ShopOnly), `spawnWeight`, `clicksToCollect` (tough pixels: only the last click pays; `PixelClicker.PixelHit` event for the others), `startingAmount`, `translucent` / `materialOverride`, `glow` + `glowIntensity` (emission on a runtime material copy + point light), `vacuum` flag, `spawnSwitch` (Auto = only Vacuum/Obsidian/Singularity/Ghost/Meteor get a spawn toggle in the Toggles window; `spawnDisabled` saved; `CanSpawn` used by `PickSpawnTier`), `flyAway`/`flyDirection`/`flySpeed` (old pixel streaks away in a straight camera-relative line with a trail instead of falling - Meteor), `count`, `totalCollected`, `unlocked`.
- Spawn: weighted random among **unlocked** tiers only (`PickSpawnTier`).
- Click flow (`CollectInternal(bool automatic)`): `AddCurrency` → `PixelCollected` event → click effects → `Vacuum()` if vacuum tier → `SpawnFallingCopy` → roll next tier → `Materialize`.
- Events: `CurrencyChanged`, `CurrencyGained`, `PixelCollected(tier, amount, automatic)`, `PixelsVacuumed(vacuumTier, total, count)`, `VacuumBreakdown(double[] perTier)`.
- Shop reward tiers are added to `PixelClicker` at runtime via `EnsureTier` (locked until bought). `EnsureTier` and Awake must only **raise** `Count`, never wipe typed starting values.
- `PixelShop.EnsureDefaultPacks()` (called from `Awake` and editor-only `OnValidate` via `delayCall`) walks the `BuiltInPacks` table and inserts any missing built-in pack into the serialized list so it is editable in the Inspector. One toggle: `addDefaultPacks`. Context menu: "Add Missing Default Packs". Older saved data is upgraded by `MigrateOldPackData()`.

## Changelog workflow (standing instruction from the user)
- The pause menu's **Changelog** screen shows `Assets/Resources/Changelog.txt` (one change per line, newest shown first).
- **After every change you make, append one line** to that file: `[YYYY-MM-DD HH:MM UTC] what was added/changed/fixed` (get the time with `date -u +"%Y-%m-%d %H:%M"`). Keep it one plain-language sentence; commit it with the change.
- When the user says to **clear the changelog** (they're making a build), empty the file (keep the file, zero lines) and commit.

## Active conventions
- **Every variable must be editable in Unity**: `[SerializeField] private` + `[Tooltip]` (+ `[Header]` grouping). Nested config classes are `[Serializable]`.
- Field initializers don't apply to already-serialized components → use Awake/OnValidate fix-ups for new defaults. No native-object constructors (`new RectOffset`) in field initializers.
- Version guards: `FindFirstObjectByType` vs `FindObjectOfType` (`UNITY_2023_1_OR_NEWER`); `PhysicsMaterial`/`linearDamping` vs `PhysicMaterial`/`drag` (`UNITY_6000_0_OR_NEWER`); `InputSystemUIInputModule` vs `StandaloneInputModule` (`ENABLE_INPUT_SYSTEM && !ENABLE_LEGACY_INPUT_MANAGER`). Input must work with both legacy and new Input System.
- UI is code-built: ScreenSpaceOverlay Canvas + CanvasScaler (1920×1080 ref, match 0.5) + GraphicRaycaster; auto-create EventSystem if missing; TextMeshProUGUI only. **One shared font** via `PixelClicker.UIFont`; every UI script applies it. Avoid obsolete TMP properties (`enableWordWrapping`).
- UI layout: line pitch ≥ 1.3× font size, header height computed from font; toggle boxes have no close "X" (clicking the button toggles); titles capitalised ("Currency", "Log", "Shop").
- Clicks on UI must not hit the pixel (`EventSystem.IsPointerOverGameObject`); pixel hitbox is a full-size trigger so rapid clicks during materialize aren't lost; use `Physics.RaycastAll` with `QueryTriggerInteraction.Collide`.
- Scripts depend on each other (`FormatNumber`, `VacuumBreakdown`, `UIFont`, …). **Always copy the whole `Assets/Scripts` folder together** – most past compile errors (CS0122, CS1061, CS0246, CS0111) were stale/mismatched copies in the Unity project.
- Git: develop on `claude/pixelclicker-initial-script-un1ao1`; commit + push when work is done; no PRs unless asked.

## Roadmap / open notes
- The UI helper (`PixelUIKit`) and minigame base (`PixelMinigame`) refactors are verified in Unity by the user.
- Cleanup still worth doing: (`PixelShop` is now split into three partial-class files; a deeper split into separate logic and UI classes is still possible); (the shop's "add missing defaults" code is now one table-driven loop; potions/devices/achievements keep their own small versions); optionally replace scene searches with one shared game object that owns the references (the version-check duplication is already gone via `PixelFind`).
- Possible next steps (not requested yet – confirm before building): more shop packs/tiers, particle polish, filling in sound clips, balancing pass on spawn weights and costs, prestige, prefabs for the runtime-built UI.
- Known gaps: offline progress only covers the auto clicker (no minigames/devices offline); active potion and placed devices aren't saved; `PixelLog` keeps a duplicate number formatter (`FormatAmount`) separate from `PixelClicker.FormatNumber` – could be unified.
