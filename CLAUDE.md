# Pixel Clicker – project notes

3D incremental clicker in Unity (C#, TextMeshPro). All code lives in `Assets/Scripts/`. Everything UI is built at runtime (no prefabs/scene UI required). Nothing has been compiled or run by Claude – the user tests in Unity.

## Core architecture

| Script | Role |
|---|---|
| `PixelClicker.cs` | Core. **Click-me hint:** while the Inventory UI's guide text ("Click N more...") shows and nothing has been collected yet (`PixelClicker.ClickHint`, set by `PixelUI.UpdateGuide`; `ClickHintPulse`), the cube pulses bigger / brighter (`clickHintAmount/Brightness/Speed`, `disableClickHint`). Manual clicks on the cube are rate-limited by `minClickInterval` (0.07 s; ignores clicks that come sooner; auto clicker, hose and minigames are exempt). Owns the `PixelTier[]` list, currency counts/totals, click handling (raycast), spawn/materialize/pulse/hover/spin animation, old-pixel "falling copy" physics (half-size copies, pop in tiny + no collision, swell-and-shrink despawn), vacuum suction, **bright falling pixels** (`brightOldPixelTypes` = Luminescent: extra emission `oldPixelGlowBoost` + a fading light trail, `lightTrail*` settings), shared UI font (`UIFont`), `FormatNumber` (public static). Also defines helper MonoBehaviours `ScaledGravity` and `OldPixelInfo` at the bottom of the file. |
| `PixelLooks.cs` | Per-pixel-type 3D look, separate from the tier data (the UI keeps the tier colour): `PixelLook` list on `PixelClicker` (`looks`, `useLooks`; defaults from `PixelLooks.CreateDefaults()`): colour override + alpha, metallic/smoothness, plain emission, neon edge outline (no pixel type uses it by default now; runtime-built mesh of 24 thin boxes with vertex colours, `Sprites/Default` material), surface texture (`streakTexture` white streaks on black, `damageCracks`: cracks that spread with every hit on a tough pixel, drawn by `PixelLooks.SurfaceTexture` and set per hit via `PixelClicker.SetLiveDamage`; used by Obsidian; the live cube's property block is cleared in `ApplyTierLook`), jelly `wobble` (live cube scale in `AnimatePixel`; falling copies draw on a child `Wobble Visual`), old-pixel physics per look (`customPhysics`: bounce/friction/`gravityMultiplier`; `ignoreViewBounds` read by `PixelViewBounds` via `PixelClicker.IgnoresViewBounds`; `floatAway` -> `OldPixelFloat`: after N ground bounces it stops colliding, drifts up/sideways and is removed off-screen; used by Ghost), gravity well (`gravityWell`, `wellRadius`, `wellPullSpeed`, `wellGrip`, `wellRingOpacity`: `OldPixelGravityWell` drags other old pixels toward it at a constant speed (overrides floor friction; works while carried with Pixel Grabbing) while it is at full size, plus a very faint camera-facing ring sprite; used by Singularity, whose spawn weight is 0.08; **each well holds at most `wellMaxPixels` (20) pixels at a time**: it keeps the nearest unclaimed old pixels in its radius (a pixel is claimed by one well only, `OldPixelGravityWell.claims`), other Singularity pixels inside the radius count towards the 20 so wells packed close together starve each other and have to be spaced out; the well pixel itself lasts `wellLifetime` = 300 s (5 min, set in the well's `Start` via `OldPixelDespawn.SetLifetime`) and every old pixel inside its pull radius is kept alive by `OldPixelDespawn.KeepAlive()` each physics step, so it doesn't age while the well works; a flying meteor pixel within `wellFlyReach` (4) pull radii is steered towards the well (turn rate 5 rad/s, slowed) and, once inside the ring, captured: `PixelClicker.LandFlyingPixel` + its speed cut to 20%, then it is dragged in like the others), face circles (flat black discs on the 6 faces, used by Vacuum), dark-matter core (counter-spinning cube with a runtime swirl texture), `lightning` (Electric: `PixelLookLightning` builds a dynamic mesh of jagged crossed-ribbon bolts along the 12 edges + a few arcs through the inside, re-rolled ~12x/s on unscaled time, a wide soft glow pass + a thin bright core pass, simpler when more than 6 exist; unlit vertex colours via `OverlayMaterial`; `lightningCoreColor/GlowColor/Jitter`), `forceTranslucent`, and `shatter` (glass: `OldPixelShatter` breaks the old pixel into `OldPixelShard`s when it hits the ground; the pixel is removed without payout; sound `glass_shatter`). Live-cube extras are managed by `PixelClicker.UpdateLiveExtras`; old pixel copies get them in `SpawnFallingCopy`. |
| `PixelCameraIntro.cs` | Camera intro (added by `PixelClicker.Awake`): the camera holds a close-up side view of the cube (`closeDistance` (1.8 cubes), `closeHeightInCubes`, `side`, optional `startFieldOfView`) while the title screen shows - the blurred title picture is that view - then after `startDelay` it swings round the cube on an arc and settles into the scene's own camera pose over `introSeconds` (the end pose is whatever the camera has in the scene, nothing to set up; orthographic cameras zoom instead). A mouse click skips it (`skipOnClick`, off by default); clicks are locked during the zoom-out of a brand-new game (`ClicksLocked`, `lockClicksOnNewGame`). `PlayReverse(onDone)` plays the zoom backwards (`reverseSeconds`) for Quit > Main menu. Player switch: Settings > Camera intro (`PixelCameraIntro.Enabled`, applies next start). |
| `Editor/PixelShaderKeepAlive.cs` | Editor-only (`[InitializeOnLoad]`, menu Pixel Clicker > Rebuild Shader Keep-Alive Materials): creates tiny materials in `Assets/Resources/PixelShaderKeep` with `_EMISSION` / transparent keywords switched on (URP Lit, Simple Lit, Standard). **Needed because builds strip shader variants no saved material uses**, which killed every glow / lava crack that is switched on from code with `EnableKeyword` (Luminescent, Solar, Meteor, bomb / pad lights). Any new runtime keyword toggle needs a matching keep-alive material. **Because that alone did not fix builds, glow no longer relies on keywords only:** `PixelLooks.AddGlowShell` draws a thin unlit coloured copy of the mesh (Sprites/Default, `OverlayMaterial`) over every glowing / emissive non-translucent pixel (plus a separate soft billboard halo `AddGlowHalo`, hidden with `hideGlowHalo`) (live cube `UpdateGlowShell`, falling copies, `CreateDisplayPixel`; `disableGlowShell`, `glowShellExtra` on PixelClicker - stored as "off" / "extra" so a scene serialized before the fields existed still gets the shell) and over the meteor rock (lava-crack overlay texture `rockLavaOverlay`). Face marks (Vacuum circles, colour-blind shapes) use `PixelLooks.OverlayMaterial` (render queue after the pixel). |
| `PixelShaders.cs` | `PixelShaders.SpriteDefault()`: the only place that looks up the Sprites/Default shader (unlit, alpha-blended, vertex colours - trails, glow shells, face marks, arrows, stars, hole trails). `Shader.Find` only finds shaders that are in the build, and a URP project often leaves Sprites/Default out, so it falls back to the shader of `Resources/PixelShaderKeep/Sprites_Default` (made by the Editor keep-alive script). **Use it instead of `Shader.Find("Sprites/Default")`.** |
| `PixelFind.cs` | `PixelFind.First<T>()` / `Count<T>()`: the only place with the `FindFirstObjectByType` / `FindObjectOfType` version check. Use it instead of calling Unity's Find methods directly. |
| `PixelUIKit.cs` | Shared static helpers for code-built UI: `EnsureEventSystem`, `CreateCanvas`, `CreateText`, `CreateButton`, `Stretch`, `CreateDropdown` (arrow = a drawn triangle sprite), `CreateInputField`, `Caps(label|button)` (UpperCase font style: **every window title and tab label is shown in capitals**), close buttons (a button labelled "X" draws a cross sprite via `UseCloseGlyph`; the shop's own `CreateButton` does the same), `CreateScrollView`/`UpdateScrollView` (masked scroll list + auto-hiding scroll bar). UI scripts delegate to it instead of carrying their own copies. |
| `PixelMinigame.cs` | Abstract base for minigames (registry `PixelMinigame.All/Find(id)`, `Id`, `Running`, `Activate/Deactivate`, optional goal tracker: `HasTracker`, `TrackerTitle/Description/Count/Goal`, `RequirementFormat`, `GoalReached`). Bought minigames get an on/off row in the Toggles window (`PixelMinigame.UserDisabled`, saved per minigame; the shop never auto-starts a disabled one). Shop packs refer to minigames by id (`unlocksMinigame`; goals via a `PackRequirement` of kind `MinigameGoal`); the shop shows tracker rows and the save system stores counts generically - **a new minigame needs no changes to PixelShop or PixelSaveGame**. For the dev tools' **Despawn** button a minigame must call `Track(go)` on everything it puts in the scene (roots, messages, effects) and override `OnDespawned()` to reset its busy flag / spawn timer (`DespawnNow()` stops its coroutines and destroys the tracked objects). |
| `PixelBlackholeMinigame.cs` | Black hole minigame (Minigames tab, a pack with `unlocksMinigame = "blackhole"`): random-size swirling hole (runtime-drawn spiral textures) opens on the floor; old pixels inside are taken via `PixelClicker.ReleaseOldPixel` and spiral in (`SpiralIn`: eased start, angular speed grows as it falls, rotates to the path and stretches into a curved streak, darkens, fading trail, `AbsorbFlash` at the centre). While a hole is open it sets `OldPixelDespawn.Frozen` (old pixels stop ageing, time dilation; `freezeOldPixels`). A live counter (TextMeshPro, `showHoleCounter`) floats above each hole but is hidden until a pixel is consumed or the mouse hovers the hole (`counterShowOnHover`), stays `counterVisibleSeconds` then fades (`counterFadeSeconds`), and the first hole ever shows a tip box (`PixelNotice`, `firstHoleMessage`, PlayerPrefs `PixelClicker.Hint.BlackHole`). The shop row text is `requirementLine` ("Feed {1} pixels to black holes: {0} / {1}") and the Minigames-tab description is `trackerHelp`. Owns the **singularity tracker** (`SingularityCount` / `SingularityThreshold`, saved); extends `PixelMinigame` (id `blackhole`); the Singularity Pixel pack has a `MinigameGoal` requirement for `blackhole`. Shop shows the tracker row on the Minigames tab. |
| `PixelMinigameLimits.cs` | Limits how many minigames have something on screen together (`minAtOnce` 2 / `maxAtOnce` 3, `limitAtOnce`, `quietSecondsAfterPlay` 30 (nothing spawns that soon after Play; `PixelTitleScreen.PlayTime`), `retrySeconds`; added by `PixelClicker.Awake`). Each minigame overrides `PixelMinigame.Busy` and asks `PixelMinigameLimits.AllowAnother(this)` before its timer spawns something (a number between min and max is rolled each time); `SpawnNow` (dev tools) ignores the limit. **A new minigame must do the same.** Minigames that take over the floor's old pixels (Snake, Sorting Race) override `PixelMinigame.Takeover` and set `PixelMinigame.TakeoverActive`; `AllowAnother` refuses every minigame (takeover or not, and the Stardust stars) while a takeover round is `Busy`, and Pixel Grabbing / cube clicks are off meanwhile. The Ultra Pad and Black Hole never spawn on top of each other: `PixelMinigame.ClaimArea` / `AreaFree` keep a list of the round floor areas in use, and each one's `TryPickSpot` rejects spots that overlap the other's. |
| `PixelGhostMinigame.cs` | Ghost minigame (bought in the shop's Minigames tab via a pack with `unlocksMinigame = "ghost"`): a faint wobbling cube floats across the screen at random intervals; the ghost carries a small glass cube with the chosen potion's pixel cube inside (`PickRandomBuff` at spawn, `BuildPotion`); clicking it drops the potion (`DropPotion`: rigidbody, shatters on first hit or after `dropMaxSeconds`, glass shards like the glass pixel, sound `glass_shatter`) and the free buff starts then (`PixelConsumables.ApplyBuff`; `GrantRandomBuff` is the fallback when no potion could be picked); counts toward `GhostsCaught` (saved); extends `PixelMinigame` (id `ghost`); the Ghost Pixel pack has a `MinigameGoal` requirement for `ghost`. PixelShop finds/adds this component. **Backpack (needs Pixel Grabbing bought + on, `PixelGrab.CanGrab`):** the falling potion has air drag (`grabFallDrag`) and can be grabbed with the mouse (`potionGrabRadius`, kinematic follow, throw on release); a semi-transparent pixel-art backpack icon (bottom right above the bar, `backpackSize/Margin/Alpha`) shows while it falls; releasing over the icon keeps the potion (`KeepPotion`, `PixelConsumables.AddKept`, no shatter, no buff) and, if that potion is already at its limit, raises that potion's `bonusCap` by one (permanent, saved as `PotionSave.bonus`; `ItemCapacity(item)` = `maxPotionsHeld` + bonus drives `ItemRoom`/`ClampHeld(index, n)`/the shop's Full text), so e.g. 16 held can be used down to 6 and re-bought to 16. |
| `PixelMeteorMinigame.cs` | Meteor minigame (pack `unlocksMinigame = "meteor"`, Minigames tab): a large glowing meteor (runtime-built: lumpy noise-displaced rock mesh `lumpiness`, lava-crack albedo/emission textures `lavaCracks`, a camera-facing glow sprite `haloOpacity`, a two-layer tail incl. a white-hot `hotCoreTail`, a particle-system ember stream `embersPerSecond`, flickering light) drifts slowly across the screen; each click gives `chunksPerClick` meteor chunks but never destroys it. | `PixelGuideVendor.cs` | **Cubby, the suspicious cube guide / shopkeeper** (added by `PixelClicker.Awake`; code-drawn teal cube with darting sideways eyes, hat, smirk; slides in like the visitors, time stops, a paged speech box, Next button or Escape = next page). **Visit 1** (new game, after the intro tips, `calmSeconds` (1.5) of calm): "show me you have money" - he leaves and you click pixels. **Visit 2** (when `PixelShop.ShopAvailable`): introduces the shop, hands over a **gift** (`giftTypes` random unlocked pixel types, `giftMin..giftMax` each, given when the page containing `{gift}` shows, a gift box appears in his hand), says more vendors will come and can be switched off in the Toggles menu, mentions the Wizard. Progress = stat counters `guide.stage1/2` (saved with the game); a save that already has the shop gets no visits and no gift (stages set silently). `PixelGuideVendor.Pending/Visiting` hold back the shop tutorial; Settings > Replay tutorial calls `PixelGuideVendor.Replay()` (clears the stage counters, both visits play again, no second gift). **The vendors are free now:** the Wizard / Tinkerer / Pixel Entrepreneur packs were removed from the shop (`MigrateOldPackData` drops them from saved lists); the guide starts them (`StartVendors`: Wizard right after visit 2 with a first visit in `wizardFirstVisitMin..Max` s, Farmer at `farmerAtTiers` (5), Tinkerer at `tinkererAtTiers` (6) unlocked pixel types, Entrepreneur at `entrepreneurAtTiers` (8); a vendor the player switched off in Toggles is never restarted; `PixelVisitorMinigame.ScheduleFirstVisit`). ### Data model
- `PixelTier`: name, colour/`UIColor`, `PixelType` enum (White, Gray, Black, Red, Green, Blue, Glass, Vacuum, Obsidian, Luminescent, Singularity, Ghost, Meteor, Solar, Electric, DragonCube1-7, Mirror, Seed, Water), `TierUnlockMode` (PreviousTierThreshold / ShopOnly), `spawnWeight`, `randomPayout` + `payoutMin/Max` (a random whole amount per harvest, e.g. Electric 1-15; `amountPerClick` = the average for estimates; migrated by `packDataVersion` 3), `clicksToCollect` (tough pixels: only the last click pays; `PixelClicker.PixelHit` event for the others), `startingAmount`, `translucent` / `materialOverride`, `glow` + `glowIntensity` (emission on a runtime material copy + point light), `vacuum` flag, `spawnSwitch` (Auto = only Vacuum/Obsidian/Singularity/Ghost/Meteor/Electric/Mirror/Seed/Water get a spawn toggle in the Toggles window; `spawnDisabled` saved; `CanSpawn` used by `PickSpawnTier`), `flyAway`/`flyDirection`/`flySpeed` (old pixel streaks away in a straight camera-relative line with a smooth tapered trail instead of falling - Meteor; `flyRandomDirection` + `flyAngleRange` 10-170 deg = a random direction on the top half of the screen), `count`, `totalCollected`, `unlocked`.
- Spawn: weighted random among **unlocked** tiers only (`PickSpawnTier`).
- Tough pixels raise `PixelHit` for hits 1..n-1 and `PixelFinalHit` (UI shows 'n/n', then the payout popup follows after `toughPayoutDelay`) on the breaking click. Click flow (`CollectInternal(bool automatic)`): `AddCurrency` → `PixelCollected` event → click effects → `Vacuum()` if vacuum tier → `SpawnFallingCopy` → roll next tier → `Materialize`.
- Events: `CurrencyChanged`, `CurrencyGained`, `PixelCollected(tier, amount, automatic)`, `PixelsVacuumed(vacuumTier, total, count)`, `VacuumBreakdown(double[] perTier)`.
- Shop reward tiers are added to `PixelClicker` at runtime via `EnsureTier` (locked until bought). `EnsureTier` inserts new shop tiers before the Dragon Cubes (rare drops stay at the END of the tier list). `EnsureTier` and Awake must only **raise** `Count`, never wipe typed starting values.
- `PixelShop.EnsureDefaultPacks()` (called from `Awake` and editor-only `OnValidate` via `delayCall`) walks the `BuiltInPacks` table and inserts any missing built-in pack into the serialized list so it is editable in the Inspector. One toggle: `addDefaultPacks`. Context menu: "Add Missing Default Packs". Older saved data is upgraded by `MigrateOldPackData()`. It also removes a leftover "Pong" pack (name or minigame id `pong`) from the saved list and renumbers the other packs' requirements.

## Active conventions
- **Every variable must be editable in Unity**: `[SerializeField] private` + `[Tooltip]` (+ `[Header]` grouping). Nested config classes are `[Serializable]`.
- Field initializers don't apply to already-serialized components → use Awake/OnValidate fix-ups for new defaults. No native-object constructors (`new RectOffset`) in field initializers.
- Version guards: `FindFirstObjectByType` vs `FindObjectOfType` (`UNITY_2023_1_OR_NEWER`); `PhysicsMaterial`/`linearDamping` vs `PhysicMaterial`/`drag` (`UNITY_6000_0_OR_NEWER`); `InputSystemUIInputModule` vs `StandaloneInputModule` (`ENABLE_INPUT_SYSTEM && !ENABLE_LEGACY_INPUT_MANAGER`). Input must work with both legacy and new Input System.
- UI is code-built: ScreenSpaceOverlay Canvas + CanvasScaler (1920×1080 ref, match 0.5) + GraphicRaycaster; auto-create EventSystem if missing; TextMeshProUGUI only. **One shared font** via `PixelClicker.UIFont`; every UI script applies it. Avoid obsolete TMP properties (`enableWordWrapping`).
- UI layout: line pitch ≥ 1.3× font size, header height computed from font; the Inventory and Log boxes have a centred title and a close "X" in a header above the tabs (clicking their button also toggles); titles capitalised ("Currency", "Log", "Shop").
- Clicks on UI must not hit the pixel (`EventSystem.IsPointerOverGameObject`); pixel hitbox is a full-size trigger so rapid clicks during materialize aren't lost; use `Physics.RaycastAll` with `QueryTriggerInteraction.Collide`.
- Scripts depend on each other (`FormatNumber`, `VacuumBreakdown`, `UIFont`, …). **Always copy the whole `Assets/Scripts` folder together** – most past compile errors (CS0122, CS1061, CS0246, CS0111) were stale/mismatched copies in the Unity project.
- Git: develop on the branch the session names (recently `claude/intelligent-cori-y2qt3d`); commit + push when work is done; no PRs unless asked.
