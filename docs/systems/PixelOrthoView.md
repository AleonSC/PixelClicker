# PixelOrthoView

## PixelOrthoView.cs

**Flat view** (added by `PixelClicker.Awake`; Settings > Display > 'Flat view' = `PixelOrthoView.Enabled`, PlayerPrefs `PixelClicker.Setting.FlatView`, off by default, synced per save in `PixelSettingsSync`): switches the main camera to orthographic so there is no depth shrinking. The size is `depth x tan(fov/2) x sizeFactor` at the cube's distance (`CubeBasePosition`), recomputed every frame while flat, so the cube keeps its on-screen size and the zoom key / orbit camera (which move the camera) still zoom. Blended in and out over `blendSeconds` (0 = 0.6) by mixing the perspective and orthographic projection matrices (`PixelOrthoView.Blend`, 0..1). It stays perspective while the title screen shows, the camera intro moves or the camera swings back to the main menu (those lerp the field of view); the blend starts when that ends. `[DefaultExecutionOrder(200)]` so it runs after `PixelZoom` / `PixelOrbitCamera`, which also write the camera in LateUpdate. A camera that is already orthographic in the scene is left alone.

Things that assume a perspective camera and were adapted: `PixelViewBounds.EdgePlane` (orthographic rays are parallel, so each edge plane is built from the ray origins) and its plane cache (ortho flag / size), `PixelFloor.FitToView` cache (ortho size), and `PixelUIKit.ViewHeightAt(cam, depth)` (use it instead of computing the view height from `fieldOfView`; the Bomb and Ghost minigames and `KeepOnScreen` use it). Not adapted: the other minigames' depth placement (they still work: positions come from `ViewportToWorldPoint`), the horizon / fog look (there is no vanishing horizon).
