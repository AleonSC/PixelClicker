## PixelShop.cs / PixelShopUI.cs / PixelShopDefaults.cs

One `partial class PixelShop` in three files: **PixelShop.cs** = data types, ALL `[SerializeField]` settings, lifecycle, buying/requirement logic; **PixelShopUI.cs** = building and refreshing the UI (button, panel, tabs, scroll list, upgrades window, trackers); **PixelShopDefaults.cs** = the built-in pack definitions (`Create…Pack`) plus the `BuiltInPacks` table (how to recognise each one, which pack it requires, how to build it) - **to add a built-in pack: write its `Create…Pack` and add one line to the table**. Keep new serialized fields in PixelShop.cs so the Inspector order stays stable. Shop button (appears once `requiredTier` = Black is unlocked) + panel. (Vacuum spawn weight 0.28 and Electric 0.2 since `packDataVersion` 11, was 0.2 / 0.15) NOTE: some entries below are outdated - the Seed, Water, Electric, Obsidian, Wizard / Tinkerer / Entrepreneur and Pixel Grabbing packs are no longer separate shop packs (their blocks now come with the Farmer's, Electrician's and Prospector's packs, the vendors are started by Cubie, and Pixel Grabbing is unlocked from the start with a Toggles switch); The cracked shell does NOT spawn an old pixel: `CollectInternal` calls `PixelClicker.SpawnSeedSprout` `seedsPerShell` (0 = 3) times (all sprouts together capped by `seedSproutCap` 36; each seed has its OWN despawn timer `seedSproutLifetime` (0 = 45 s from dropping, `SeedSprout.SetLifetime`: it withers if its pixel hasn't popped yet) and the pixel it grows is an ordinary old pixel with its own normal timer) -> `SeedSprout` (PixelSeed.cs): a big green sprout (`seedSproutScale` 2.2x an old pixel, `PixelLooks.CreateSproutObject`) tumbles down (it never collides with the live cube and is a trigger for `popNoCollisionSeconds` after it is born, `SeedSprout.SetGhost`, so a burst of sprouts doesn't pile up inside the cube), plants itself upright on the first flat contact (dirt puff, a pushed-up dirt mound and a soft green point light make it easy to spot), then (`seed_plant`: a small code-made crunch, `PixelSynth.Crunch`, played by every `SeedSprout.Plant` and when the Seed pet plants itself) over `seedGrowSeconds` (6) a display model of a RANDOM unlocked pixel type grows from nothing on its tip (`CreateDisplayPixel`), holds `seedHoldSeconds` (1) wobbling, and pops off as an ordinary old pixel (`SpawnStoredPixel`, payout `RollOldPixelAmount`); the sprout then shrinks away. **Rarer types are likelier** (`RandomSeedPixelTier`: chance ~ 1 / spawnWeight^`seedRarityBias` (1); not rare drops / fly-away / Seed / Singularity), **never a Vacuum or Singularity pixel (those only come from bought seeds)**. **Old Solar pixels within `seedSolarReach` (6 old-pixel widths) speed growth** (`SolarSeedBoostAt`: +`seedSolarBoostEach` (0.75) each, capped at `seedSolarBoostMax` (3); the sprout's light turns warm yellow while boosted). **Solar clusters:** old Solar pixels that touch each other (centres within `solarClusterDistance` 1.5 old-pixel widths, connected groups) in a group of `solarClusterSize` (5) or more never despawn (`PixelClicker.UpdateSolarClusters`, every 0.15 s `OldPixelDespawn.KeepAlive()`; the old-pixel cap still removes the oldest). **Seeds never sit on top of each other:** `PixelClicker.SeedSpotFree(pos)` (spacing `seedSpacing`, 0 = 0.7 x a sprout's width; `SeedSprout.AnyNear`, `PixelPets.PlanterNear`) is checked when you plant (message), when the Seed pet sows (it tries another spot) and `PlantSeedSproutAt` refuses; a shell sprout that lands too close slides away (`SeedSprout.MakeRoom`). Sprouts are not saved; stored Seed pixels (Bank, saves) are plain shells), Water Pixel (Pixels tab, listed right after Seed / before Electric, `PixelType.Water`, **TESTING price: 10 White, no requirements** so it is available at once - raise it later; pays 3, spawn weight 0.4; look = see-through wobbling blue jelly (`wobble`, `forceTranslucent`, `looksVersion` 15); `packDataVersion` 10 moves it into place; has a spawn switch in Toggles): **old Water pixels are used up by splashing**: `OldPixelSplash` (PixelSeed.cs, added in `SpawnFallingCopy` when the look has `splash`) splashes the pixel the first time it lands on the ground (not on other pixels, not while held; or after lying still 1.5 s), whether or not anything needed water: `ReleaseOldPixel(body, false)` (no payout), `WaterSplashFx` (blue droplets + mist particles), sound `water_splash` (`PixelSynth.Splash`) and `PixelClicker.WaterSplashAt` gives every growing `SeedSprout` and planted Seed pet within `seedWaterReach` (5 old-pixel widths) an INSTANT jump of `seedWaterGrowSeconds` (1.5 s of growth / sowing time), but each target accepts water only every `seedWaterCooldown` (0.75 s) so Sorters / auto clickers can't make it instant (a splash flashes the sprout's light blue); **Solar pixels make them 'sun soaked'**: any old Solar pixel near a sprout / pet sets it soaked for `seedSunSoakSeconds` (8) at the boost it gave, so the speed-up outlasts the Solar pixel. A soft ray of sunlight (`SunRayFx` in PixelSeed.cs: two crossed vertical ribbons fading upward, unlit vertex colours, shimmering, fades in/out) stands over every sun soaked sprout / planted Seed pet. (a wet sprout's light is blue (`looksVersion` 16 switches splash on in saved Water looks); a Sorter streaming Water pixels over sprouts makes a farm. Mirror Pixel (Pixels tab, listed before Vacuum, needs the Electrician's Pack (it used to need the Electric pack), 15K each of Red / Green / Blue, pays 4, spawn weight 0.2, `PixelType.Mirror`, chrome look (`PixelLook.chromeTexture`: a code-drawn sky / horizon / ground texture so it reads as reflective in any render pipeline, plus emission, and `shine`: `PixelLookShine` sweeps a SOFT diagonal band of light across each face in turn (the overlay mesh is an 8x8 grid per face, `PixelLooks.ShineGrid`, and the vertex alpha follows a moving band so it fades at the edges - the old single quad could only blink as a white rectangle)) added by `looksVersion` 11 and replaced by 14, moved into place by `packDataVersion` 6; **a click on a Mirror pixel also pays the last other pixel type's last click amount again** (`PixelClicker.lastReflectTier/Amount` in `CollectInternal`, raises `PixelCollected` for it too, so Overcharge / pets react)), Electric Pixel (**no longer its own pack: it comes with the Electrician's Pack**, random 1-15 payout, spawn weight 0.2; older saved lists were migrated by `packDataVersion` 4-5, `MovePack` reorders a pack and renumbers requirement indexes). The shop's tracker rows (one per minigame with a goal counter) are off by default (`showMinigameTrackersInShop`): they moved to the Log's Goals tab. The Upgrades tab has **two** sub-tabs: **Features** (the packs; `featuresSubTabText`, renamed from "Upgrades") and **Value** (`upgradesSubTab` 0/1). The old "Pixel" Ultra-boost page was removed (Ultra pixels will get a different use): `PixelTier.ultraLevel`, `UltraMultiplier` and `PixelShop.TryBuyUltraBoost` still exist, nothing in the UI buys them. **Value upgrades** = the idle-game growth engine: one row per unlocked pixel type, paid in that pixel's own currency, cost `valueBaseCost x amountPerClick x valueCostGrowth^level` (25, 1.15, no cap by default, `valueMaxLevel`), **Value rows: the orange '!' says 'Each level multiplies this pixel's worth per click by that level.' (`valueInfoText`) and hovering the Upgrade button shows just 'Shift-click to buy as many as you can.' (`valueUpgradeTip`)**; **every shop row is boxed** (`StyleBoxedRow(row, rightInset, hasLevel)`, called after the picture is added: pack, potion, Value, Operation, Operation-upgrade and search rows): a sunken box beside the orange '!' button holds the name (single line, shrinks to fit), a same-height box to its right the level (`row.levelLabel`, only on leveled / Value rows; leveled rows put the little level markers at the right end of the cost box via `ApplyLevelWidgets`), a larger box underneath the cost lines (`row.costBox`), and the buttons stay on the right (`LayoutPackRowLikeCards`, the old wide Buy bar along the bottom, is no longer called); Shift-click buys up to `valueMaxBulk` (`PixelInput.ShiftHeld`); payout x `(1 + level * valueBonusPerLevel) * valueMilestoneMultiplier^(level / valueMilestoneEvery)` (`PixelClicker.ValueMultiplierAt` / `ValueMultiplier`; settings in PixelClicker "Value Upgrades"). `PixelClicker.PayoutMultiplier` = Ultra x Value, used for click payouts and offline progress. `PixelTier.valueLevel` is saved in `TierSave`. Potion/device prices paid in a pixel type are multiplied by its Value multiplier (`PixelConsumables.pricesScaleWithValue`, inside `ItemCosts`). The Consumables tab now has **two rows of purchase cards** (`cardRowHeight` 322): Potions + Utilities, then **Seeds** (`seedsCardTitle`, lists only seed items, same drop-down / count / Buy as the others); card titles are capitals, the cost line starts with 'COST:', and there is no description text: an orange '!' box left of the cost line shows the item's description as a wrapped tooltip (`PurchaseCard.tipText`). **Every shop row (packs, potions, Value rows) works the same way:** `LayoutRowHeader` puts the '!' box (`CreateInfoBox`) in front of the name, hides the description label (`PackRow.descLabel` stays as hidden storage for the tooltip text) and gives the freed space to the name / cost bands; the mouse-over sets `hoverTip` (a `Func<string>`), drawn by the currency tooltip in `UpdateCurrencyAndWindows` + a blank spare card (`PurchaseCard.blank`, for later). **The Pixels tab is split into collapsible sections** (`SectionOf`: Base pixels = RGB / Glass / Luminescent packs, Toggleables = single other pixels, Skill packs = packs with 4+ reward pixels; header buttons `sectionHeaders`, `sectionCollapsed`). **Search box** at the window's top left (`searchField`, `searchPlaceholder`, `searchWidth`): while it has text `RefreshRows` ignores tabs / sections and lists every pack matching `MatchesSearch` (name, description, reward pixel names); matching consumables (potions, devices, seeds, supplies; `RefreshSearchItems`, one row each, Buy x1), Value rows and Operation rows are listed too, the cards, sub-tabs and trackers are hidden meanwhile; `SelectTab` clears it. Four tabs (Pixels / Upgrades / Consumables / Minigames; per-pack `tab`, `Automatic` infers it) over a fixed-size scrolling list (ScrollRect + scrollbar). Leveled packs that require another pack (the auto clicker upgrades) are not in a tab: the required pack gets an arrow button opening a second "Upgrades Window". Each pack has a `requirements` list (`PackRequirement`: kind `Pack` = another pack index must be bought, kind `MinigameGoal` = a minigame id's goal reached; all must be met; `ShopPack.ParentIndex` = first Pack requirement, used to file upgrade packs under their parent). The **Combo Meter is listed right above the Auto Clicker** (table order + `packDataVersion` 16 moves it in saved lists). **`PixelShopCurrency.cs`** (partial): the **currency panel** on the left of the shop window (child of the shop panel, so the shop itself is not moved; `hideCurrencyPanel`, `currencyPanelWidth/Gap/RowHeight/IconSize/FontSize`): a scrolling list of unlocked (or held) pixel types, each a spinning `PixelCubeIcon` in the tier colour + the amount, hover tooltip (`PixelHoverTip`) with name + full amount. Opening the shop closes the Inventory and Log (`UpdateCurrencyAndWindows`), and opening the Inventory or Log closes the shop (`PixelShop.CloseShopWindow`). When the shop closes it brings back the Inventory (or Log) it closed on opening (`reopenInventory/reopenLog`), unless the player opened another window meanwhile. Every number in the shop uses `PixelClicker.FormatNumberShort` (always abbreviated from 1K, ignores the setting). Handles buying, requirements, affordability colouring, levels/upgrades, Inspector-ticked `purchased`. `[RequireComponent(typeof(PixelAutoClicker))]`.
