## PixelCrafting.cs

Crafting (shop pack with `unlocksCrafting`, Upgrades tab): bottom-right "Crafting" button opens a window laid out like the SHOP: the window takes the shop window's size (`PixelShop.PanelSize`, capped to the space between the black bars) and a **Materials panel** hangs off its left exactly where the shop's Currency panel is (`BuildMaterialsPanel`, width / gap = `PixelShop.CurrencyPanelWidth/Gap`): a scrolling list of one row per owned item formatted like the Currency rows (spinning cube - or a glass cube with a smaller pixel cube inside for potions - on the left, small name on top, bold amount underneath; drag a row into a box or click it). The window itself holds the two drop boxes, a recipe/cost readout and a Craft button in a `Body` that `FitWindow` centres a little in the free height. Drag (or click) grid items into the boxes; `Recipe` list in the Inspector (two ingredients, pixel currency or potions, any order -> a potion or device); defaults = each pixel + Glass -> that pixel's potion; plus automatic combo recipes: **a potion + ANY pixel -> a 2-type combo potion, and a 2-type combo potion + one more pixel -> a 3-type combo potion** (Vacuum and Dragon Cubes can't be part of a combo) (`FindComboRecipe`, `ResultKind.Combo` / `Triple`; `PixelConsumables` craft-only potions that spawn their 2-3 types evenly via `PixelClicker.SetForcedSpawnTiers(a, b, c?)`; ALL pair and triple potions (~1100) are generated once at start by `AppendComboPotions` (flagged `craftOnly`, `hasThird` / `thirdType`, looked up by a bit mask `comboLookup`, `FindComboPotion(a, b[, c])`) so item indexes never shift; hidden from the shop; the save stores only the ones you hold, `PotionSave.second/third`, `activePotionThird`; the Inventory makes a potion's row only when first held, `CreatePotionRow`). Combo ingredients are `Ingredient.combo/second/hasThird/third` (runtime) and `Item.hasThird/third`. **Easier crafting:** clicking a row in the Materials list puts that item in the first free box (`QuickPlace`); clicking a KNOWN recipe in the Recipe Book fills both boxes with its ingredients (`FillBoxes` / `Decompositions`; auto-filled boxes are `pinned` so they stay even if you lack the item); with one box filled, every Materials row that makes nothing with it is greyed out and can't be clicked / dragged (`Cell.disabled`); **Craft x1 / x5 / Max** buttons above Craft (`craftAmount`, `MaxCraftable`, the Craft button reads 'Craft x N'; recipe stats are counted per canonical key `recipe.c.<sorted types>`); the Recipe Book lists every Recipes entry + every 2-type combo (??? until crafted) + only the 3-type combos you made, has a **search box** (known recipes only, `bookSearch`) and its known rows are clickable (fill the boxes). Right-click a box to empty it. **The boxes** are sunken frames with a glowing rim and a breathing '+' while empty (`AnimateSlots`), and the how-to text is gone: hovering a box shows `slotTipText` and hovering a material `materialTipText` in a small tooltip that follows the mouse (`craftTip`, `UpdateTip`; hidden while dragging). A hand-drawn **book button** (top-left of the window) toggles the **Recipe Book** (`BuildBook`): a panel to the RIGHT of the window, as tall as it and as wide as the Materials panel (like the shop tutorial's 'Got it' boxes), recipes as uniform two-line rows (`BookLine`: the result in bold, what it is made of dimmer underneath); Escape closes it first: `AllRecipes()` = the Recipes list + every automatic combo recipe; a recipe is shown once it was crafted (`PixelStats` counter `RecipeKey(r)` = `recipe.<kind>.<potion>.<second>.<device>`, set in `Craft`; owning the result also counts) and as `???` otherwise. **Crafting level** (placeholder, nothing uses it yet): every craft gives XP (`XpPerCraft`: potion `xpPotion` 5, 2-type combo `xpCombo` 12, 3-type `xpTriple` 25, device `xpDevice` 30, per craft made, plus `xpDiscovery` 20 the first time a recipe is crafted; 0 = default) into the stat counter `crafting.xp` (saved generically); `CraftingLevel` / `LevelOf` (level 2 needs `xpFirstLevel` 40, each next `xpGrowth` 1.35 x more); a level bar with 'Crafting level N - x / y XP' runs along the bottom of the window (`BuildLevelBar`, `RefreshLevelBar`), a level-up posts an event-log line, and every craft shows its own cyan '+n XP' that rises over the bar (`ShowXpPopup`, separate from the cursor / cube +n popups). Spends via `PixelClicker.TrySpend` / `PixelConsumables.TryRemoveItem`, adds via `AddItem`. PixelShop finds/adds it.

**Crafting update (current).** Every pixel except the Dragon Cubes has a single potion now (pixel + Glass; `IsStandalone` types too: ores, skill blocks, Fire...). Combo potions (2 / 3 types) still use only the non-standalone pixels (`AppendComboPotions`, `FindComboRecipe`: standalone pixels would make tens of thousands of combos and their enum values are past the 64-bit `Bit` mask). The Recipe Book is EMPTY at the start: `RecipeKnown` is only true once the recipe was crafted (stat `RecipeKey`), no more `???` rows and owning the result no longer counts. The Materials panel has a search box (`materialSearch`, filters by name, ignores folded categories while searching) and foldable category headers Pixels / Potions / Devices (`materialsCollapsed`, `MaterialHeader` pool, `RefreshList` lays headers and the pooled cells out by y).
