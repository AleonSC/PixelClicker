## PixelUIKit.cs

Shared static helpers for code-built UI: `EnsureEventSystem`, `CreateCanvas`, `CreateText`, `CreateButton` (**EVERY button is made by it**, directly or through a thin per-script wrapper (MakeButton / CreateButton / AddButton in the pause menu, title screen, Shop (+ press pulse and fancy-menu shine), Log, Inventory, Dev Inspector, Dev Mockup, Feedback, window chrome, PixelDevUI.Button, PixelTalk mute); it already plays the `ui_click` sound, so callers must NOT play it again; an icon button = CreateButton with an empty label plus drawn children (Skills Guide Book, skill-tree square). Things that are clickable but are NOT buttons - list rows (Bank, Crafting recipes / categories, the event log, Pocket log lines), pictures (Collection Log pages and camera, favourite star, pet pencils, Gauntlet faces / stones, Pocket + card), click catchers (visitor peek), the title wanderers' toggles - keep their own look and go through `MakeClickable(go, onClick, sound, pressTint, target)` (plays `ui_click` unless `sound: false` because the click makes its own sound; `pressTint: false` for scroll-list rows and plain pictures). **Enforced:** `tools/compile-check/rules.sh` fails the compile check on any `AddComponent<Button>` / `typeof(Button)` outside PixelUIKit), `Stretch`, `CreateDropdown` (arrow = a drawn triangle sprite; EVERY drop-down in the game is made by it - no hand-built popup lists; list entries are as tall as the box; `escapeMasks: true` = the opened list escapes a clipping scroll view, same as `LetListEscapeMasks`), `CreateLookDropdown(..., source)` (a drop-down of every look of an `IPixelLookSource` with preview pictures; its `PixelLookDropdown` component applies picks and follows look changes made elsewhere; used by the Settings floor / sky rows and the title screen pickers), `CreateInputField` (white 3 px blinking caret, placeholder hidden while focused), `AddSearchIcon(field)` (magnifier inside a search box; used by every search box), `Caps(label|button)` (UpperCase font style: **every window title and tab label is shown in capitals**), arrow buttons (`UseArrowGlyph(button, pointLeft)` swaps a "<" / ">" letter for a drawn triangle: the shop's Back button in the sub window (Pixel Bank / Auto Clicker upgrades), the floor / sky pickers, the pet outfit arrows), **UI colour** (`PixelUIKit.UiColorOn` / `UiHue` / `UiSat`, PlayerPrefs `PixelClicker.Setting.UiColor/UiHue/UiSat`, Settings > Interface, synced per save; **there is no slider: an eyedropper button beside the 'Custom UI colour' tick box picks the colour from the screen** (`SetUiColorFromColor` takes its hue and saturation, switches the colour on): `Tinted(colour)` keeps a window colour's brightness but gives it the chosen hue; `StyleWindow` remembers every window image so `RefreshWindows()` recolours them live), **bar glow colour** (`PixelHud.GlowHue` / `GlowCycle`, `PixelBarGlow.EdgeColor(baseHue, time, speed, offset, sat)`), **boxes** (`PixelUIKit.StyleBox(image, inset)`: rounded, softly shaded list rows / cards with a thin lit rim, `inset` = a sunken frame for 3D pictures; used by the Shop rows, currency rows, cards and picture frames), **fancy windows** (`PixelUIKit.StyleWindow(image, colour)` gives every window background a code-drawn rounded 9-slice frame with the colour baked in - gradient, bright cyan rim, inward glow; always on (the old flat-window switch and its Settings toggle were removed); **new windows should call `StyleWindow` instead of setting `Image.color`**), **fancy buttons** (always on, the flat-button switch was removed: `CreateButton` uses a code-drawn grey-scale 9-sliced `ButtonSprite` - rounded corners, dark outline, gradient, light top strip - tinted by the button colour; the shop's own button builder calls `PixelUIKit.StyleButton` too), close buttons (a button labelled "X" draws a cross sprite via `UseCloseGlyph`; the shop's own `CreateButton` does the same), `TickSprite()` (code-drawn check mark used as the fill of every tick box), `CreateScrollView`/`UpdateScrollView` (masked scroll list + auto-hiding scroll bar). **Every scroll bar uses `PixelUIKit.StyleScrollBar(track, handle)` (slim `ScrollBarWidth` 10, rounded dark track + lighter rounded handle): new scroll bars must call it. **Bottom fade:** while a list scrolls and isn't at its end, `PixelScrollBarFade` fades the ROWS (direct children of the scroll content, each given its own `CanvasGroup`: alpha follows the row's centre height above the view's bottom edge, `fadeHeight` 44 x 1.6) plus a bobbing chevron below the list; nothing is drawn over the window and the mask is untouched (an earlier soft-mask version let rows ghost over the tabs at the top). Not for drop-down templates or views without a RectMask2D. `StyleScrollBar` also adds `PixelScrollBarFade` (CanvasGroup alpha: visible while scrolling / hovered / held, `holdSeconds` 0.45 after the last movement, then fades in `fadeSeconds` 0.18). UI scripts delegate to it instead of carrying their own copies.

### Custom UI button colour
Settings > Interface > 'Custom UI button colour' (tick box + eyedropper, PixelUIKit.ButtonColorOn / SetButtonColorFromColor, PlayerPrefs PixelClicker.Setting.UiButtonColor / UiButtonHue / UiButtonSat, per save via PixelSettingsSync). PixelUIKit.StyleButton registers every button image and its base colour; RefreshButtons recolours them all at once (neutral buttons take the picked hue, strongly coloured ones such as red Quit keep theirs; a button whose colour something else changed, like a selected row, is left alone). Replaces the retired 'Pixel-assemble menu buttons' effect (PixelDockFx).


## Button roles (UI unification step 3)
- Make a button by MEANING: `PixelUIKit.CreateButton(font, parent, name, label, size, ButtonRole.X, labelSize)`; switch it later with `PixelUIKit.SetRole(button or image, role)` (a tab: `SetRole(img, open ? ButtonRole.Selected : ButtonRole.Neutral)`; an on/off toggle: Success when on, Neutral when off). Never set a role button's `Image.color` by hand.
- Roles and their colours live in `PixelUITheme` (a system component, Inspector-editable): Neutral (ordinary, window X / header buttons, inactive tabs), Primary (main action, every '?' help button), Selected (open tab / chosen item), Success (green confirm), Danger (red quit / delete / reject). Neutral, Primary and Selected follow the custom button colour; Success and Danger keep their meaning colour (ticks in the Inspector).
- A plain colour (`CreateButton(..., Color color, ...)`) = role Custom: only for truly unique colours (a skill's accent, a vendor's theme colour, gold); weakly coloured Custom buttons still follow the custom colour (the old rule).
- Not a button but should look like one (a colour swatch, a progress trough, a list row): `StyleButtonLook(image)` - the shape only, never recoloured.
