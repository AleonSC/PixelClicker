# PixelSaveGame

**Save registry (2026-10-18; overrides the per-system wording below).** Systems save themselves: they implement `IPixelSaved` (SaveId, SaveOrder, Export, Import) and register with `PixelSaveRegistry` in Awake (see its header for the load-order bands). The save file keeps one list `SaveData.parts` (id + JSON). Now on the registry: auto clicker (`autoClicker`), Pixel Grabbing / Time Stop / Combo switches (`grab`, `timeStop`, `combo`), pets (`pets`), the UFO job + switch (`ufo`), the event log (`eventLog`), potions + devices held (`inventory`), placed devices + running potion (`inventoryWorld`), achievements, stats, the Bank. PixelSaveGame itself still writes the core: tiers, Ultra, shop packs, minigame counters, husks, settings, the Dev Hub tester machines, plus `playSeconds` as a summary for the slot list. A new thing to save = implement IPixelSaved on its system; nothing to add here.

## PixelSaveGame.cs

Save/load to JSON in `Application.persistentDataPath` (tiers, shop packs by name, auto clicker, potions owned). Also saves the **running potion** (type, combo second type, seconds left; restored after `FinishLoad` via `PixelConsumables.RestoreActive`) and the **placed devices** (`PixelConsumables.PlacedState`: device name, position, yaw, seconds left, a Charge Booster's charge (aim), device extras; `GetPlacedDevices` / `ClearPlacedDevices` / `RestorePlacedDevice`; every `PixelPlacedDevice` knows its `DeviceIndex`). Time away does not run their timers down. Loads on start (1 frame delayed), autosaves (shows a small pulsing "Autosaving..." note at the bottom right above the black bar: `ShowAutoNote`, `autoSaveNote*` fields; manual saves keep the centred message), saves on quit. **Save slots**: `slotCount` slots (slot 1 = the old `saveFileName`, others `..._slotN.json`); `CurrentSlot` (PlayerPrefs, the slot autosave / quit-save / startup load use; set by `SaveToSlot` / `LoadSlot`); `SlotHasSave`, `TryGetSlotInfo`. The pause menu's single "Save / Load" entry opens a window (`BuildSaveLoadPanel`): scrolling slot list of compact rows (name + a Rename button that opens a text box via `OpenRename` / `ConfirmRename`; names live in PlayerPrefs `PixelClicker.SlotName.N`, empty = 'Slot N'; date / time played / pixels show in a hover box, `UpdateSlotTip`), select one, Save / Load buttons, an overwrite warning (`BuildOverwriteOverlay`) when saving over an existing slot. After a save or load in that window a **blue result window** the size of the whole menu (`BuildResultOverlay` / `ShowResult`, `resultColor`, texts `savedResultFormat` etc.) says "Saved to slot N" / "Loaded slot N" (or the failure) with a "Got it" button (Escape closes it too); those calls pass `message: false` to `SaveToSlot` / `LoadSlot` so the centred toast doesn't also show. Restart deletes the current slot's save. Uses `PixelClicker.LoadTierState/FinishLoad` and `PixelShop.SetPackState`. **Husk positions** are saved (`SaveData.oldPixels` = `PixelClicker.OldPixelState`: tier, payout, position, rotation, velocities, `OldPixelDespawn.Remaining`; not flying / vanishing ones; skipped while a takeover minigame has moved them) and restored by `PixelClicker.RestoreOldPixels` after `FinishLoad` (older saves leave the pixels alone). **Settings per save file** (`SaveData.settings`, `PixelSettingsSync.cs`): `Collect()` copies a fixed list of PlayerPrefs keys (`PixelClicker.Setting.*` except display hardware, `PixelAudio.*`, `PixelClicker.Key.*`, `PixelClicker.Dev.*`) into every save, `Apply()` writes them back on load (keys not in the file are deleted = defaults; an older save without the list changes nothing) and `Reload()` calls each cache's reload (`PixelClicker.ReloadSettingsFromPrefs`, `PixelShop`, `PixelKeys`, `PixelAudio`, `PixelDisplaySettings`, `PixelPauseMenu`, `PixelHints.RefreshLog`, `PixelDevTools.ReloadFromPrefs`). Resolution / fullscreen / VSync / quality / UI scale and the 'seen tip' flags stay global. **A new PlayerPrefs setting that should follow the save file must be added to the list in `PixelSettingsSync.Known_` (and its cache reloaded in `Reload`).**

**Autosave list + screenshots (current).** Every TIMER autosave (not manual / quit saves) is also copied into `<persistentDataPath>/Autosaves/autosave_<ticks>.json` (+ `.meta` info, + `.jpg`), at most `autosaveHistorySize` (100, Inspector; `keepAutosaveHistory`) - when full the OLDEST are deleted (`PixelAutosaves.Add` / `Trim`). The Save / Load window has a small 'Autosaves' button under Save | Load that opens `PixelAutosaveWindow` (PixelAutosaves.cs): newest first, a Load button per row (`PixelSaveGame.LoadFile`, the current slot does not change; the game resumes), hover = screenshot + details. EVERY save writes a screenshot next to it (`<save file>.jpg`, 320 px wide, `PixelSaveShots`: taken at the end of the frame while the game is visible; a rolling copy every 4 s is used when saving from the pause menu) and the slot rows' hover box shows it above the details (`PixelPauseMenu.UpdateSlotTip`, `SlotThumbPath`). Deleting a save deletes its screenshot. With the autosave interval set to Off there are no autosaves to list.

**Save rework (current; overrides the slot / autosave wording above).** Autosaves (timer, quit, focus loss, Quit > Main menu - `Save(bool)`) go ONLY into the autosave list (`PixelAutosaves.Add`, always kept, at least 1); the numbered slots are written ONLY by a manual save (`SaveToSlot`). Quit / focus-loss saves within 5 s of the last autosave are skipped; no autosave happens on the main menu, and the timer pauses (not resets) on the title screen and while the pause menu is open. `TryGetLatest(out slot, out path)` = newest file among manual slots and the newest autosave (slot 0); Continue and the startup load use it (`ContinueMostRecent`). The save's name is `SaveData.slotName` (`GetSlotName` / `SetSlotName`; a name for an empty slot waits in PlayerPrefs `PixelClicker.SlotName.N` until the first save). Settings follow the profile: while the title shows, the newest save's settings are applied (`ApplyProfileSettings`) and Continue of that same file does not re-apply them; a new game / Restart calls `PixelSettingsSync.ResetToDefaults` (keys and volumes stay) and sets `AutoStartNewGame`. Restart deletes the autosaves only (`PixelAutosaves.DeleteAll`).

## Look settings are NOT per save
`PixelSettingsSync` stores per-save settings in the save file and puts them back on load / start. The look of the interface (UI colour + hue / saturation, button colour, neon bar glow + hue / cycle / picked colour, bar colour, clicker aura + colour / mode) is deliberately left out of its `Known_` list: those PlayerPrefs belong to the player's machine. Kept per save they were overwritten on every start by the newest save's copy, so anything changed after the last save was lost.
