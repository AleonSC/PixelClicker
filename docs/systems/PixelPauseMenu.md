## PixelPauseMenu.cs (Settings screen)

The Settings screen is a scrolling list with section headers (Gameplay, Interface, Saving, Display, Audio, Controls). Row helpers: `AddSettingToggle` (re-reads its value whenever the screen opens via `settingsRefreshers`), `AddChoiceRow` (a button that cycles the options on click - dropdowns don't work inside scroll lists), `AddWideButtonRow`, `AddHeaderRow`. **Accessibility section** (collapsible header after Interface): cube rotation (switching it off restores the cube's scene pose, `PixelClicker.startRotation`), pulsing, colour-blind marks, click effects level, popup size, event log size, UI scale. Interface: first-time tips (`PixelHints.TipsEnabled`) + Replay tutorial (`PixelHints.ReplayTutorial`), event log on/off + text size (`PixelHints.EventLogEnabled/LogSizeChoice`), number popups on/off + size (`PixelUI.PopupsEnabled/PopupSizeChoice`), UI scale, colour-blind marks. Saving: autosave interval + message (`PixelSaveGame.AutoSaveChoice/AutoSaveMessageChoice`). **Menu search** (top right of the main screen, 'Paused' is left-aligned: `menuSearchField`, `OnMenuSearchChanged`): hides the button grid and lists matching menu entries plus up to 6 matching settings rows (`settingsItems` labels); a settings result calls `OpenFilteredSettings` (`settingsFilter`: `LayoutSettings` then shows only matching rows and their headings, folded or not); the search clears each time the menu opens. A Key Bindings screen (`BuildKeysPanel`, click a key, press the new one, Escape cancels) opens from Controls. **Row widths:** every row under a section header (toggles, choice rows, sliders, wide buttons) is `SettingsRowInset` (112) narrower than the list, exactly the Replay tutorial button's width. **Per-save settings sync:** `PixelSettingsSync.Known_` lists each PlayerPrefs key with its TYPE (0 int, 1 float, 2 string) - a key registered with the wrong type is read as 0 and overwritten on load (that wiped the eyedropped glow colour, the hues and the skill pack); an entry stored with another kind than the key's is ignored.

## PixelPauseMenu How To Play (tabs)

The pause menu has one **Game Guide** button (between Settings and Give feedback; it was called How To Play) that opens a screen with three TABS: **Controls**, **How To Play** (the written guide) and **Database** (opens the game database window) - the tabs: **Controls** (`Controls.txt`, formerly the pause menu's Controls button) and **Game Guide** (`HowToPlay.txt`); each tab is its own `GuideScreen` panel and the tab buttons switch between the panels (`BuildGuideScreen(..., isControlsTab)`). **Settings ends with a 'Keybinds' header** with one 'Change keybinds' button that opens the key-binding screen (titled 'Keybinds').

## PixelPauseMenu Game Guide panels (current: the tabs above switch between these two panels)

Two more screens that show **`Assets/Resources/HowToPlay.txt`** and **`Assets/Resources/Controls.txt`** (the user edits these files; `GuideScreen`, `BuildGuideScreen`, `RefreshGuideScreen`, `FormatGuideText`). File format: lines starting `//` are hidden notes, `# Heading` = coloured heading, `Key | Action` = two columns, anything else is shown as written (TMP rich text allowed). **When a keybind or control changes, update `Controls.txt`; when a major system is added, update `HowToPlay.txt`.**
